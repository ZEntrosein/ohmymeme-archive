# OhMyMeme

轻量化跨平台表情包管理系统 — 突破表情包上限，快捷键呼出、搜索即复制。

### **QQ交流群：891636253**

## 功能

- **Esc 逐层返回** — 在表情包或聊天记录详情页按 Esc 只关闭详情、返回主页面；焦点落在图片或弹窗外也能返回，长按不会连带隐藏主窗口。回到主页面后，再按一次 Esc 沿用原有隐藏窗口行为（不退出后台程序）；详情里的下拉候选仍优先收起。

- **子页面暂停拖放导入** — 详情、标签编辑等子级弹窗打开时，不显示主窗口导入遮罩，也不会把拖动的文字、图片或文件当作导入；编辑框内仍可原生拖动文本调整位置，关闭弹窗后自动恢复拖放导入。

- **详情键盘编辑** — 表情包和聊天记录详情支持 Enter 跳到下一个可编辑输入框，Ctrl+Enter（macOS 为 Cmd+Enter）保存，Ctrl/Cmd+S 仍可保存。多行文本用 Shift+Enter 换行；中文输入法确认、下拉候选选择和标签添加保持原行为，最后一项不会循环或自动保存。

- **Windows 热键消息循环兼容** — 在项目兼容层修正 `keyboard` 后端的消息缓冲区与退出判断，避免心跳自恢复结束旧线程时触发空指针异常，不修改已安装的第三方库文件。

- **详情固定操作栏** — 表情包和聊天记录详情的「关闭 / 保存更改」固定在弹窗右下角，滚动信息或消息内容时仍可直接操作；窄窗口也无需滚动到底部。

- **详情遮罩防误关闭** — 从详情页内拖选文字、移到弹窗外松开鼠标时不会关闭；只有在外围遮罩上按下并松开的正常点击才会退出，关闭按钮和 Esc 不受影响。

- **侧栏切换保留页面** — 切换「分组 / 类别」标签页只更换左侧列表，右侧内容、路径导航、子文件夹、页码、搜索筛选及已选表情保持不变，方便将当前页内容拖到另一种归属栏；点击具体节点时才切换内容页。

- **系统托盘运行** — 最小化资源占用，后台常驻；右键菜单中文（显示/隐藏、退出），托盘后端不兼容时自动回退英文
- **单实例运行** — 重复启动时自动检测已有实例（Windows 命名 mutex / POSIX 锁文件），Windows 弹窗提示后退出、其他平台静默退出，避免多开引起的数据冲突
- **全局快捷键** — 默认 `Ctrl+Alt+N` 呼出/隐藏主面板；Windows 可选在鼠标所在屏幕显示隐藏的主面板，默认关闭。内置运行期自愈：回调异常不会拖垮键盘监听线程，守护线程周期性检测监听线程存活，Windows 下另以无害 F15 探针（每 30s，由内部阻塞钩子拦截，不会泄漏到前台窗口）验证键盘钩子未被系统静默移除，任一失效自动重启监听并重新注册，无需重启软件；热键相关事件（注册/异常/线程死亡/自愈）会追加到 `data_dir/hotkey.log` 便于排查
- **表情管理** — 导入/搜索/标签分类/收藏/自定义分组与单归属类别
- **一键复制** — 点击表情包自动复制日常副本到剪贴板（GIF 保留动画）；右键「复制原件」可复制未经日常压缩的文件。Windows 可选在全局快捷键呼出后安全尝试粘贴回原窗口。仅由全局快捷键从隐藏状态呼出的主窗口，会在复制成功后自动隐藏，普通窗口、托盘呼出及复制失败时保持可见
- **批量操作** — 多选模式下支持批量加入分组/设置类别/移动到分组/打标签/删除；类别选择器可搜索完整路径、输入 `/` 新建多级类别，或设为「未分类」。批量换类会替换原有单归属类别并同步移动原件，不改变分组和标签；批量打标签为合并追加，不清空各表情已有标签
- **原生文件拖拽** — 关闭拖拽排序后可将日常副本拖到外部应用。静态图片和 GIF 拖到 QQ 时都可在设置中选择通过 NapCat 按表情包发送，避免被当作普通大图；拖到其他软件仍是普通文件。仅由全局快捷键从隐藏状态呼出的主窗口，会在拖拽成功后自动隐藏，普通窗口、托盘呼出及拖拽失败时保持可见
- **自适应日常副本** — 普通导入保留原件，同时生成用于预览、普通复制和拖拽的副本：静态图转 WebP，GIF 保持 GIF，动画 WebP 保持 WebP；最长边收敛到 1600px并保留透明通道和动画。文件超过 20 MiB 时默认弹窗选择保留原件或仅归档压缩版，可勾选保持选择，也可在设置中预设；聊天记录媒体不受此项影响，始终保存原件。超大 JPEG 会在 3 亿像素硬上限内先由 JPEG 解码器降采样，避免完整展开到内存。旧数据或恢复/同步得到的原件会在首次使用时自动补建副本
- **复制处理** — 设置页四种模式（不处理 / WebP 缩放 / 转 GIF / 转 GIF 隐写原图）：以日常副本为输入，对超过设置尺寸（默认 200px）的静态图继续按所选模式处理；右键「复制原件」始终绕过这些处理。导入含隐写的 GIF 会自动解码并只入库还原后的原图，载体 GIF 不入库
- **拖放导入** — 直接拖拽图片到窗口即可导入；安装桥接插件后，QQ 商城表情和合并转发聊天记录也默认支持直接拖入，无需手动开启诊断模式。聊天记录通过两分钟内、只能消费一次的本机随机凭证交给已鉴权的 NapCat 插件恢复，不把聊天正文或媒体路径写进系统拖放数据。导入成功后只刷新当前视图，不会修改用户当前的体裁、搜索、标签、分组或类别筛选
- **文件夹导入** — 一键导入整个文件夹的图片，可选自动创建同名分组
- **编辑框文字复制** — Windows 主窗口和设置窗口的普通文本输入框支持 Ctrl+C、右键复制进入 Win+V 本地历史，同时明确禁止云剪贴板同步。密码框和密码自动填充字段保留浏览器隐私行为，不改变图片复制、剪切或非 Windows 的行为。
- **近似图片提示** — 单张导入遇到内容近似的已有图片时，显示候选缩略图、名称与文件名，并提供保留新图、保留旧图、都保留或跳过。候选使用已保存的文件哈希读取缩略图，优先复用本地缩略图和日用副本。
- **重复图片定位** — 导入已有图片或相似图选择“保留旧图”时，沿用最近使用定位，但保留图片、GIF、聊天记录的当前勾选，不再自动全选或覆盖已保存的体裁偏好。定位后的列表仍按当前体裁过滤。
- **表情包详情** — 右键选择「查看表情包详情」或长按卡片打开；左侧用日常副本按原始比例大图预览，悬停可用左右按钮浏览全图库，也支持 ←/→ 快捷键；右侧明确显示并可编辑标题、文件名、单归属类别（可选择多级类别）、所属分组（显示完整层级路径，可搜索添加或移除）、标签，以及彼此独立的人工/AI 图片描述和人工/AI 图片文字。搜索不存在的分组或类别名称时可就地创建顶层或子节点并选中；节点创建立即生效，但当前表情的归属仍需点击「保存更改」才会写入，文件名或类别保存时同步移动实际原件（扩展名保持不变）。升级前已有的描述与文字保留在 AI 字段，新增的人工字段默认留空；切图前会尝试保存，关闭、Esc 或点击遮罩会放弃未保存修改，长按触发后不会复制到剪贴板
- **聊天记录详情** — 聊天记录拥有独立于 QQ 来源摘要的可编辑名称，并显示可编辑的媒体文件夹名；修改文件夹名时同步重命名 `chat-record-media` 下的实际目录并更新全部媒体引用。重新导入或重新读取同一条来源消息不会覆盖用户设置的名称和文件夹名；类别、分组、分类标签及选择性发送规则仍在同一详情页管理
- **聊天记录文字复制** — 详情页中的消息正文、引用文字、发言者、时间、记录名称和来源信息支持鼠标拖选后按 Ctrl+C 复制；不改变排版或字号，也不影响分类管理、媒体预览和发送屏蔽控件。
- **右键菜单** — 查看表情包详情/复制原件/重命名/收藏/打标签/添加分组/加入分组（任意视图可用，子菜单列出全部分组树，顶部可即时搜索完整分组路径）/从分组移除/删除；表情卡悬停显示快捷收藏按钮，侧边栏分组悬停显示「⋯」快速操作入口
- **删除即时刷新** — 单张、批量及聊天记录删除成功后会等待当前内容、标签、分组和类别统计刷新；清单采用不读取原件的增量移除，虚拟盘或大图库也无需等整库扫描后卡片才消失
- **设置界面** — 表单改动未保存时关闭会提示确认；局域网开关/密钥传输/存储位置等立即生效的选项带「立即生效」标注
- **上游 0.7.0 集成** — 主窗口与设置页支持深浅主题、可选边框缩放和尺寸记忆；新增插件管理、启动媒体及顶栏扩展、云端同步状态面板、按远端清单差集上传、分组清单开关与 WebDAV 自签名证书确认。保留本分支的 NapCat、类别目录、压缩导入、虚拟盘保护及全部自定义设置；复制仍默认使用原有 WebP 缩放模式，可另选“仅修改后缀为 GIF”。
- **分类标签、体裁与搜索** — 标签按种类分组展示和筛选，同名标签可存在于不同种类；表情包详情与右键「打标签」均可保留或指定标签种类，详情中的编辑按钮可全局修改现有标签的名称和种类。标签栏最前方另有不可编辑的系统「体裁」筛选，图片、GIF、聊天记录可以独立勾选，显示所有选中体裁的合集；首次使用全部选中，之后自动保存体裁勾选状态，关闭或重启应用后恢复上次选择（包括全部取消），无需额外点击保存。全部取消则显示空列表，不改变当前分组或类别，也不会混入普通标签或被重命名。关键词始终匹配文件名和标签，并可在「设置 → 基础设置 → 搜索范围」分别控制图片描述、图片文字是否参与检索；启用后会同时搜索对应的人工与 AI 字段，聊天记录按标题匹配
- **悬停放大预览** — 鼠标悬停 0.5s 自动浮出完整原图（横向长图在格子内被裁切，悬停即可看全图），移开/滚动/Esc 即收起；设置页「悬停预览」开关可关闭（默认开）
- **复制时避免 WebP** — 设置页开关（默认关闭）：开启后复制路径上的产物不含 WebP，动图 WebP 转 GIF、静态 WebP 转 JPG（带透明的缩放产物转 PNG），用于兼容微信等把 WebP 当文件的应用；**动图转 GIF 时按尺寸上限等比缩小**（GIF 无帧间压缩且逐帧整幅写入，长动图体积可远超原图，实测全库 56 个动图可由 84MB 降至 22MB）；库内文件不变，仅生成临时转换副本，转换失败回退原图并记录日志
- **设置向导** — 首次启动（或旧版本升级后）弹出 7 步向导：欢迎、全局快捷键录制、开机自启、动图自动播放、云端同步（可跳过）、导入表情（可跳过）、完成；关闭向导（含 ESC/×/完成）即写入 `config.json` 的 `guide` 标记（本机配置，不进同步清单），下次启动不再提示
- **首次运行环境检测** — Windows 首次启动弹出原生检测窗口（tkinter，不使用网页控件），检查 WebView2 Runtime 安装与版本（≥ 94.0.992.0，即本项目经 pywebview 6 实际所需：其初始化时无条件调用的 `IsSwipeNavigationEnabled` 需此版本起，门槛取 pywebview 源码阈值与该值的较大者）、.NET Framework ≥ 4.6.2；点「确定」写入 `env_check.json` 标记后不再自动显示（×/ESC 关闭不写标记，下次启动再提示），设置页「关于 → 打开环境检测」可随时重开，`--debug-env` 强制打开并输出检测详情
- **GIF 动图** — 网格内自动播放，可在设置中关闭
- **分组/类别筛选** — 侧边栏以 tabs 切换多对多「分组」和单归属层级「类别」；类别栏首项固定为“全部”，可随时清除类别筛选回到完整内容页。两个 tab 右侧均可用「＋」新建；名称中输入 `/` 可一次创建完整层级（如 `角色/爱丽丝/问候`），缺失的中间层会自动补齐，节点右侧「⋯」中的新建操作则从当前节点继续创建相对子路径。鼠标悬停任意分组或类别时，当前页中直接属于该节点或其子级的表情包会即时显示高亮框，无需切换当前筛选。可把表情包或聊天记录卡直接拖到侧栏节点，快速追加分组或切换类别，拖到「未分类」则清除类别。删除类别或分组时可选择“保留子级并提升”或“删除整棵子树”，默认每次询问，也可勾选始终使用所选方式；两种方式都不会删除其中的内容。图片换类时会同步移动原件目录，继续拖出窗口仍沿用原有文件拖放或 QQ 发送。类别父节点包含所有子类别，类别目录与 `cache_dir` 下原件路径同步，重命名/删除/详情换类会同步移动目录和文件。按收藏夹、自定义分组或类别过滤，点击标签可叠加搜索；名称未手动排序时按自然顺序展示（数字按数值 1,2,10，中文按拼音）
- **未分组 / 未分类** — 分组栏最上方固定显示“未分组”，自动汇总未加入任何分组的表情包和聊天记录；类别栏固定以“全部 → 未分类”开头，“未分类”汇总没有类别的内容。两项即使为空也保留入口
- **侧栏完整名称提示** — 鼠标停留在类别或分组节点上时，显示完整名称的悬停提示；适用于各级节点及折叠侧栏，不改变列表宽度或现有操作。
- **层级拖动** — 在展开的侧边栏中按住类别或分组，拖到同类型的另一节点上，确认后即可连同子树调整归属；拖到侧栏顶部可恢复为顶层。分组只改本地层级和路径，不移动图片；类别同步整目录移动原件，不逐个读取或重新下载。不能移到自身或后代、不能覆盖同名节点或已有目录，系统虚拟节点和“隐藏”根分组不能作为拖动源。取消确认或移动失败不会改变层级；数据库提交失败会尝试恢复原目录。普通点击、树展开按钮、右键菜单和图片/聊天记录拖放保持原用途。
- **类别内未分类** — 「设置 → 基础设置 → 侧边栏与层级」可开启“为有子类别的类别显示‘未分类’入口”（默认关闭，选择自动保存在本机配置）。开启后，每个有子类别的节点都会多一个只读的“未分类”子入口，显示直接属于当前类别、未进一步归入子类别的图片、GIF、聊天记录及云端图片，包含零条目的入口。不创建真实类别、不移动文件，也不改变原有父类别包含整个子树的行为；关闭开关时，当前虚拟入口退回对应父类别。
- **随机浏览** — 分组栏内置不可删除、不可重命名的“随机”入口，首次进入从全图库随机抽取一页图片/GIF（最多 200 张，不重复），不足一页则全部展示，并遵守“隐藏”设置。在其他页面之间切换不会重抽；停留在随机页时再次点击侧栏“随机”才换一批。结果在本次应用运行期间保留
- **隐藏分组** — 分组栏内置不可重命名、不可删除的“隐藏”根分组，可以继续建立和删除普通子分组。默认启用隐藏效果：只要内容直接属于“隐藏”或其任意子分组，就会从主页、其他分组、类别、收藏夹、最近使用以及关键词/标签搜索结果中排除，即使它同时属于普通分组也不会泄漏；只有进入“隐藏”子树才会显示。设置中可关闭该效果而不移除任何归属
- **分组/标签栏横向滚动** — 栏内溢出时显示细滚动条，鼠标滚轮横向翻页
- **侧边栏滑动手势** — 折叠时在左侧栏条上按住右滑展开，展开时在侧栏内左滑折叠，与搜索框左侧折叠按钮等效
- **本地缓存** — 原件按类别层级存放 + 可再生日常副本 + 缩略图三层存储，离线可用
- **缓存扫描** — 启动时自动扫描缓存目录，已有文件无需重复导入
- **导入限制** — 普通媒体硬上限为 200 MiB；「设置 → 导入」提供“限制导入图片的最长边”，默认关闭，开启后可设置 1–65535px 的阈值（默认 2560px）。普通导入、缓存扫描、云端下载、同步拉取和局域网导入的新记录统一遵守该开关，不影响已入库记录或聊天记录内媒体。关闭长边限制不会关闭文件大小、总像素或图片解码安全检查，也不改变日用副本与缩略图尺寸。超过 20 MiB 时按“每次询问 / 保留原件并生成压缩版 / 仅保存压缩版”三态设置处理，局域网协议帧继续使用更严格的 64 MiB 上限
- **自定义存储位置** — 设置页可更换表情包图片存放目录，切换时可选自动迁移现有文件；可显式开启 CloudDrive2 等虚拟盘兼容模式，并启用批量读取保护（分批、限速读取原件）。批量大小和暂停秒数可调，也可在后台按当前主页/搜索/分组/类别筛选逐渐缓存后续页
- **同步进度条** — 上传/下载实时显示进度、速度、当前文件，支持后台运行
- **本地备份与恢复** — 设置页一键导出全量备份 ZIP（原件 + 数据库，标签/收藏/分组/排序随库保留，不压缩省时间），日常副本不重复入包、恢复后按需重建；可选备份目录与备份列表管理，新设备空库一键恢复，仅 PC 间迁移
- **远程同步** — FTP / S3 / R2 / WebDAV 多端同步
- **云端直接使用** — 开启后本地缺失的云端表情带云角标按清单顺序与本地穿插显示在网格中（侧栏/标签/搜索/分页计数同步计入），点击即下载校验入库并自动复制使用（下载中显示遮罩，完成后遮罩自上而下退场再转为本地卡片；默认开启，可关）
- **云端与二次开发兼容** — 云端条目同样遵循隐藏分组、类别子树、分类标签及图片/GIF多选筛选；最近使用和随机页只查询本地内容。下载保留类别目录、压缩归档来源及分类标签；本地缩略图优先从日常副本生成，不改变原件或聊天记录媒体。
- **局域网互联** — 与同一局域网内的手机版 OhMyMeme 配对，互相同步表情包与配置（UDP 发现 + 密钥握手 + AES-GCM 加密会话）
- **QQ 聊天记录命令** — 连接本机 NapCat Framework，共用当前 QQ 登录态；回复一条合并转发消息并发送 `/omm`，即可保存外层来源、完整消息段和嵌套转发结构。归档会作为「聊天记录」体裁出现在主内容库，点击可查看来源、完整消息预览和发送命令，也可逐段标记「发送时屏蔽」。屏蔽不会删除归档内容，模式二、三、四重组时会略过所选段落，屏蔽嵌套记录的父节点会同时略过整个子树；模式一仍原样转发 QQ 外层原消息。在目标 QQ 会话发送 `/omm list` 可列出 ID，发送 `/omm send <ID>` 会按设置选择四种发送方式
- **手机导入** — ADB 一键从 Android 手机拉取 QQ 表情包缓存并打包 ZIP（自动识别主存储与外置 TF 卡路径）
- **电脑版 QQ 提取** — 从 PC 版 QQ（QQNT）本地缓存批量提取收藏表情（可复用模块，见下）
- **Telegram 表情导入** — 从 Telegram Desktop 本地缓存解密提取表情包（WebP 直取、WebM 转 WebP 且保留透明通道，自动跳过动态表情的静态重复版），Windows 安装包内置裁剪版 ffmpeg 无需额外安装，支持手动指定 tdata 目录并记忆
- **Notion 数据库导入** — 使用 Internal Integration 只读导入 Files & media 图片，可增减多个标签列映射，每个 Notion 属性分别导入为一种标签，并可映射标题和分组；图片保存到本地缓存，不依赖一小时有效的 Notion 临时链接
- **微信表情导入** — 从微信电脑版缓存提取收藏表情（Windows，需微信正在运行）：随包内置的 C++ 辅助二进制提取进程内存密钥（只读访问）→ AES-CBC 解密表情数据库 → CDN 下载并校验 MD5；支持多账号选择。辅助二进制随安装包分发、不在运行时下载，执行前校验 SHA-256 防篡改（不匹配即拒绝执行）
- **危险操作** — 设置页一键清空本地或云端全部数据（需双重确认）
- **无边框窗口** — 自定义标题栏，鼠标拖拽移动；点击标题栏「OhMyMeme」logo 返回主页（清空搜索/标签/分组筛选）
- **自动更新** — 启动时检测新版本，运行期间每日自动检测，下载安装包后一键升级

## 快速开始

从 [Releases](https://github.com/OhMyMeme/OhMyMeme/releases/latest) 下载对应系统的安装包或可执行文件，直接运行。

**环境要求**: Python 3.10+

```bash
git clone https://github.com/OhMyMeme/OhMyMeme.git
cd ohmymeme
pip install -r requirements.txt
python -m src
```

- 主窗口与设置页前端均为 Vue 3，源码运行时若构建产物缺失会自动执行一次 `npx vite build`

或使用 conda：

```bash
conda create -n ohmymeme python=3.12
conda activate ohmymeme
pip install -r requirements.txt
python -m src
```

## 使用

### 基本操作

1. **启动** — 运行后系统托盘出现蓝色图标，按 `Ctrl+Alt+M` 呼出主面板
2. **导入** — 点击标题栏「导入」按钮或直接拖拽图片到窗口，支持 png/jpg/gif/webp
3. **复制** — 点击任意表情包复制日常副本到剪贴板（GIF 保留动画）；需要未压缩文件时右键选择「复制原件」
4. **搜索** — 搜索栏输入关键词实时筛选；文件名与标签始终参与匹配，图片描述和图片文字可在基础设置的「搜索范围」中分别启用或关闭，启用后同时匹配人工与 AI 内容；点击标签或分组名叠加过滤
5. **表情包详情** — 长按表情包，或右键选择「查看表情包详情」；可编辑标题、文件名、单归属类别、所属分组、标签，以及独立的人工/AI 图片描述与人工/AI 图片文字。不适用的一侧可以留空，用于明确内容来源；类别以多级路径显示并同步原件目录，分组以完整层级路径显示，可搜索添加已有节点、就地创建顶层或子节点并选中，或移除归属。新节点会立即保留，当前表情的归属只有点击「保存更改」后才生效；也可用图片两侧按钮或 ←/→ 浏览全图库，长按不会触发复制
6. **右键菜单** — 查看表情包详情 / 复制原件 / 打标签 / 重命名 / 收藏 / 添加到分组 / 从分组移除 / 删除

### 收藏与分组

- 右键 →「收藏」将表情加入收藏夹，点击左上角⭐按钮筛选收藏内容
- 右键 →「添加到分组」创建或选择已有分组
- 分组显示在搜索栏下方，点击即可筛选该分组内的表情
- 切到侧边栏「分组」后可点右侧「＋」输入 `一级/二级/三级` 一次建立完整路径；已有层级会复用，缺失层级会自动创建。节点右侧「⋯」的「新建子分组路径」以该节点为起点

### 类别与文件目录

- 侧边栏「类别」tab 用于建立单归属的层级类别；一个表情包只能选择一个类别节点，点击父类别会包含所有子类别
- 类别 tab 右侧「＋」同样支持 `/` 路径；节点右侧「⋯」的「新建子类别路径」从当前类别继续创建全部缺失层级
- 类别名称会直接成为 `cache_dir` 下的目录名，例如 `角色 / 爱丽丝` 对应 `cache_dir/角色/爱丽丝/`
- 在详情中换类、重命名类别或删除类别时，原件会同步移动；删除类别/分组可按统一设置提升子级或删除全部子级，其中内容归入上一级（删除根节点时变为未分类/未分组）。多对多的「分组」仍只管理数据库关系，不改变文件路径

### QQ 聊天记录命令

NapCat 会话桥接插件的 QQ 拖放注入在后台初始化，单个窗口等待最多 1.5 秒，不阻塞其它窗口或后续插件启动。超时不取消 Electron 内部脚本；同窗口的未完成操作不会重复入队，原操作结束后才允许重试。停止／重载会使旧后台回调失效。

1. 在 NapCat 的 WebSocket 服务配置中开启 `reportSelfMessage`（上报自身消息），并在 OneBot 全局配置中开启 `parseMultMsg`（解析合并转发消息）；后者用于保留多层嵌套聊天记录。HTTP 与 WebSocket 服务使用相同的 Access Token。
2. 在 OhMyMeme「设置 → 联网 → QQ 聊天记录（NapCat）」中填写 OneBot 地址/Token，并填写 NapCat WebUI/API 地址（默认 `http://127.0.0.1:6099`）和 `webui.json` 中的 Token。WebUI 配置既用于拖拽识别当前会话，也用于 NapCat 重启后按来源会话与真实消息序号恢复原生转发。勾选命令监听后保存；默认命令为 `/omm`，可以修改。
3. 在 QQ 中回复一条“合并转发聊天记录”，只发送 `/omm`。OhMyMeme 仅接受当前账号自己发出的命令，并在原会话回复保存结果；不会读取最近会话列表。排障时也可发送 `/omm 消息ID`。
4. 保存后可在主窗口「体裁 → 聊天记录」中查看。点击卡片可浏览来源信息和归档消息预览，也可以复制该记录的发送命令。
5. 在设置页选择聊天记录发送方式，再在准备接收记录的群聊或私聊中发送 `/omm list` 查看最近归档，并发送 `/omm send <ID>`。四档方式分别是：原生转发外层原消息、重新读取原消息并重组、仅使用数据库中的本地归档重组，以及“自聊重建后原生转发”。默认仍是兼容性最好且保留真实发送者的模式一；NapCat 重启后会按归档中的来源会话和 `real_seq` 重新定位原消息。私聊归档若由 B 在 B-A 会话中导入，当 A 使用模式一或二时会安全翻转为 A-B 视角，并以 `real_seq`、时间和发送者验证原消息；当前账号不是该私聊任一方时会拒绝发送。这仍要求 A 的 QQ 历史中存在同一张外层卡片，且双方视角下的真实序号一致。模式二、三在归档含 QQNT 原生负载时能保留归档发送者和头像；新版即使 `parseMultMsg` 已把根记录直接展开为 `data.content`，也会从外层原消息另行保存该负载，模式二刷新失败时不会再覆盖已有负载。若这种内联记录没有独立的原卡片 JSON，发送插件会按实际发送节点重建外层 `news` 预览和“查看 N 条转发消息”，不再沿用临时种子卡片的“自己: 聊天记录”。存在最外层消息屏蔽项时，桥接插件会直接从原生 `MultiMsg` 负载删除对应节点，未删除节点的发送者头及未知协议字段保持原样。若筛选深入嵌套记录，或旧归档从未保存且原消息现已无法恢复原生负载，则为了保证内容完整与不漏发被屏蔽内容，仍改用本地节点安全重组，此时 QQ 可能把发送者校正为当前账号。重组媒体会保留原消息形态：普通图片继续使用 `image`，动画/自定义表情图片保留 `sub_type` 与 `summary`，NapCat 接收时兼容表示为图片的商城表情会按 `emoji_package_id`、`emoji_id` 和 `key` 还原为 `mface`；QQ 小表情、语音、视频和文件也保持各自消息段类型。重建卡片在 Windows QQ 仍可能显示“暂不支持该消息类型”。新增的自聊模式不伪造任何发送者头：它把本地归档内容逐条发到当前账号的自聊，由 QQNT 逐层生成真实卡片，再用原生 `forwardMsg` 转发到目标会话；它不依赖原外层消息，适合模式一已不可用但必须在电脑端打开的情况。代价是所有节点的发送者名称和头像都会变成当前账号，且自聊会留下构造用的叶子消息与中间卡片。该模式必须配置 NapCat WebUI 地址和 Token。本地媒体副本依然用于还原图片等内容；当前最多保留两级内层聊天记录（加上最外层卡片共三层）。
6. Windows 下也可直接把主窗口中的聊天记录卡拖到已经打开目标会话的 QQ 窗口。拖拽本身不会向输入框投递文件、文字或 `/omm` 指令；松手后 OhMyMeme 把落点 QQ 窗口句柄交给桥接插件，插件精确读取同一个 QQ 渲染窗口的顶部聊天标题，再与 NapCat 的群/好友列表唯一匹配，随后按设置中的发送方式调用 OneBot。QQNT 若在 Electron 外层增加了原生宿主窗口，导致两种句柄不同，插件仅在确认当前只有一个可读聊天渲染窗口时安全降级；有多个候选时会拒绝发送，不使用上一次会话猜测目标。这条路径不依赖“最近一次切换”状态；插件不可用时才回退到 Windows UI Automation。拖到非 QQ 窗口、目标无法唯一确定或标题不可读时会拒绝发送；按 Esc 可取消。
7. 安装项目内的 `napcat-plugin-ohmymeme-current-peer` 桥接插件，才能使用按落点窗口识别目标、跨 NapCat 重启的原生消息重定位、多层聊天记录恢复、QQ 内容拖出，以及重组聊天记录的 Windows QQNT 卡片兼容。可复制插件到 NapCat Framework 的 `plugins` 目录，或在 PowerShell 执行：`.\scripts\install_napcat_current_peer.ps1 -NapCatRoot "E:\Program_Files_tools\NapCat.Framework"`，然后完全重启 NapCat。插件加载后会自动向现有及后续新建的 QQ 渲染窗口注入拖放桥接，不需要在 OhMyMeme 设置页手动启动，也不会采集鼠标元素结构或写入专用拖放诊断日志。商城表情以临时图片文件投递；聊天记录先同步生成只含随机 ID 的 `.ommchat` 单次凭证并启动系统拖拽，然后在后台按消息 ID 和所属会话恢复完整 OneBot 结构。OhMyMeme 消费凭证后复用 `/omm` 的标准归档、媒体本地化和去重流程，只刷新当前视图。凭证两分钟过期且消费后立即删除，正文、完整 URL 和本地媒体路径不会写入凭证。插件相关路由均受 NapCat WebUI 鉴权保护，包括仅供 OhMyMeme 消费拖拽凭证的 `/consume-chat-record-ticket`。

归档兼容普通节点的 `message`、NapCat 4.18 的 `node.data.message`，以及 `parseMultMsg` 产生的 `data.content` 内联节点；嵌套转发的 `type: node` 包装也会还原为层级结构。如果 NapCat 最终仍返回没有任何正文的空节点，OhMyMeme 会拒绝保存，避免把未展开、已过期、已撤回或当前版本不支持的内容误存成完整归档。已经保存的旧空节点会在详情和重组发送时显示明确占位。媒体归档会沿资源引用和全部内联节点递归查找；图片在 `downloadRichMedia` 超时时会用原生 `picElement` 重新生成带当前 rkey 的腾讯地址，视频、语音和文件则优先复用原生消息中的本地路径或重新申请当前有效地址，再复制到永久目录。

当前版本把外层消息位置、QQ 真实消息序号 `real_seq`、全部消息段和可获取的嵌套转发资源写入本地数据库；数据库摘要中的旧短序号会在升级启动时从结构包自动修正。对同一条外层消息重复执行命令会更新原记录。保存多层聊天记录时，桥接插件会参考 QQ Chat Exporter 的做法，先按来源会话与 `real_seq` 重新找到外层原消息，再用 `MsgApi.getMultiMsg` 取得带真实 `msgId`/`elementId` 的内层消息：图片会依次尝试 QQNT 缓存、当前 rkey 地址与原生下载事件回退，视频、语音和文件会从原生元素取得本地路径或刷新 URL。成功取得的全部媒体都会复制到 `cache_dir/chat-record-media/<记录哈希>/`，每份聊天记录独占一个子目录；图片单文件上限 64 MiB，其他媒体单文件上限 512 MiB。结构包只保存相对于 `cache_dir` 的路径，因此媒体会随“表情包存储位置”迁移和本地备份一起移动，删除聊天记录时也会删除对应子目录。升级后会在后台把旧 `data_dir/chat-record-media/` 文件迁入新位置并更新引用。反馈会分别说明已本地保存和仅保留临时引用的媒体数量。升级前已经保存且引用已过期的旧媒体无法只靠 JSON 结构反推出文件本体，需要对一条仍可原生打开的新卡片重新执行 `/omm`。

回复引用的原消息也会作为 `reply.data.omm_quoted_message` 保存，引用中的图片、视频等媒体参与同一套本地化与预览流程。拖拽和 `/omm` 共用恢复链路；读取嵌套记录时始终保留最外层来源会话和根消息 ID，合并协议恢复结果时保留标准消息中的回复与 JSON 段。较长记录的桥接读取最多等待 10 分钟、响应仍限制在 64 MiB 内，同一次恢复不重复扫描原生媒体树。

原生聊天记录支持多个等价消息位置。配置 NapCat WebUI 并安装新版桥接插件后，通过 OhMyMeme 原生转发成功的目标消息会保存账号、会话、真实序号、时间和发送者，作为同一档案的副本位置；详情页的“消息位置”可查看列表。发送与模式二重新读取会优先尝试最近成功的位置，位置不可用时自动尝试其他位置，原位置不享有特殊优先权，也不会因一次失败被删除。更新归档、编辑分类或重命名媒体目录都会保留位置列表，本地整库备份也包含它。完整 QQNT 原生负载重放产生的消息也可成为等价副本；裁剪、普通节点重组和改变发送者的自聊重建不加入完整副本列表。发送已提交但回执缺失、超时或位置保存失败时不会自动重发。此功能只记录用户本来就要发送的消息，不会额外向任何会话发送备份；所有位置都被清除或当前账号均无访问权限时，仍无法保证原生转发可用。

原生转发副本可能共享 QQ 服务端的同一份转发资源。多个消息位置降低的是外层消息被清除、消息索引失效或会话不可访问造成的影响，不等于 QQ 服务端资源的永久独立备份；本地归档与媒体副本仍应保留。

「设置 → 联网 → QQ 聊天记录（NapCat）」提供“启动时清理超过一天的 QQ 拖拽凭证和占位图”，默认开启，保存后从下次 OhMyMeme 启动生效。启动后台只扫描当前用户系统临时目录的顶层，删除最后修改时间超过 24 小时、名称精确匹配插件 UUID 格式的 `.ommchat` 凭证和 `-drag-icon.png` 占位图；不清理商城表情临时图片、剪贴板缓存、正式归档或其他临时文件，也不进入子目录或跟随链接。无法读取或删除的文件会跳过，不阻塞启动；删除的是已失效的临时辅助文件，不提供恢复副本。

QQNT 本身不会把合并转发卡片作为包含 OneBot 消息 ID/资源 ID 的标准文件或文本拖出；OhMyMeme 的桥接插件会识别合并转发卡片，并从 QQ 内部消息索引恢复来源。若卡片 DOM、消息索引或原资源已失效，仍可回退到回复外层卡片后发送 `/omm`；普通 `[聊天记录]` 文本不会被误当作可恢复的结构数据。

### Notion 数据库导入

1. 在 Notion 创建 Internal Integration，并把目标数据库共享给该 Integration；只需读取内容权限。
2. 在主窗口点击「导入表情包 → 从 Notion 数据库导入」，直接在弹窗中填写 Integration Token 和数据库 URL。数据库含多个 data source 时还需填写 Data source ID。
3. 点击「测试连接」自动识别属性，也可以手工填写属性名。在「标签列」区域用「添加标签列」和删除按钮增减映射：左侧填写 OhMyMeme 中的标签种类，右侧选择对应 Notion 属性；种类留空时默认使用该属性标题。支持 Multi-select、Select、Status、Rich text 与 Relation，Relation 会读取关联页面的 Title 作为标签或分组名称。
4. 点击「开始导入」。每个标签列会按自己的种类写入，同名标签在不同种类中保持独立。原件会经过 200 MiB 硬上限、可选的最长边限制（默认关闭）和 SHA-256 去重，保存后生成日常副本；Notion 数据不会被修改。

Integration Token 在本地配置中加密保存。成功导入后会在本地数据库记录 Data source、Page、图片属性、文件位置和页面修改时间；再次导入时，未修改且本地文件仍存在的 Notion 托管图片会在下载前跳过，并继续以 SHA-256 作为最终内容去重。旧数据首次升级后需要重新下载一次以建立来源映射。Notion 的临时签名 URL 不会被保存；外部媒体 URL 因内容可能原地变化，仍会每次下载并校验，且仅允许公网 HTTPS 地址。

### 远程同步

支持 FTP / S3 / R2 / WebDAV 四种后端同步多台设备的表情包库。配置完成后点击「测试连接」验证，然后使用标题栏的⬆上传 / ⬇下载按钮同步。

标题栏云图标会显示当前同步状态：绿色对勾表示本机与云端一致，黄色感叹号表示存在差异；未配置云端时图标自动隐藏。点击图标可查看「本地缺失 / 云端缺失」文件数，也可手动重新检查云端清单。上传或下载转入后台后，图标变为传输样式并在外圈显示进度环，点击可查看剩余文件数、速度与当前文件。

> 使用 WebDAV 且服务器为自签名证书时，「测试连接」会提示证书不受信任；选择「继续使用」后会在配置中开启「忽略证书校验」，可随时在设置页关闭。

> ⚠️ 若设置中开启了「同步时删除远程文件」，上传操作会删除远程端已不存在的文件。

**云端直接使用**：设置页「云端同步」勾选开启（**默认开启**，首次配置存储类型时会弹窗以「开启/关闭」二选一确认，Esc 不改动），启动时拉取云端清单，本地表情与本地缺失的云端表情按清单顺序**穿插显示**在主网格（左下角云角标；全部/分组/类别/标签/搜索/收藏夹/未分组/未分类可见，最近使用和随机除外；分组视图按该分组子树的清单顺序，尚未推送的新导入表情排在最前），点击云卡片即下载（SHA-256 校验 + 去重）入库并自动复制使用，标签/分组/收藏由后台异步补齐；缩略图与本地统一为内容哈希命名（`/api/thumb/<sha256>`，动图缩略图为动画 WebP），滚动到缺失缩略图的云行时后台自动补拉并刷新显示（无需重启），标题栏「刷新」会同步重拉云端清单与缩略图；保存开启时会询问是否立即上传一次（含缩略图），上传后其他设备才能正常显示缺失表情。另可勾选「启动时自动补传缺失的云端缩略图」（配置 `cloud_thumb_auto_push`，默认开启）：启动后静默检测云端 `thumbnails/` 缺失项并差集后台上传（不弹进度、不打扰使用），关闭后仅在手动同步时随 push 上传。

### 局域网互联

与同一局域网内的手机版 OhMyMeme 配对，无需公网即可互相同步表情包与配置：

1. **配置** — 设置页「局域网互联」设置端口（默认 17852）与连接密钥（留空表示同局域网内无需密钥，不推荐）
2. **开启** — 勾选「开启互联访问」临时启动服务（重启后默认关闭，不写入配置）
3. **连接** — 手机版扫描局域网发现本机，输入密钥配对；配对成功后设置窗口弹窗确认设备信息，允许后才开始同步；互传表情包/配置时设置页显示传输进度（百分比/速度/当前文件，可后台运行）

局域网接收到新表情、或 NapCat 完成聊天记录归档后，主窗口会自动重新查询当前筛选并回到第一页，确保新内容立即可见；短时间内连续入库会合并为一次刷新，不会整页重载或重新扫描整个图库。
4. **安全** — 数据帧使用 AES-GCM 会话加密；设备连接需电脑端确认；配置同步默认剔除 FTP/S3/R2/WebDAV 等密码字段，开启「允许密钥传输」（仅本次会话，弹窗警示）后才会包含密钥；`push_file` 四重校验（文件名、≤64MB、sha256、合法图片），不合法字节绝不落盘

> ⚠️ 服务可被同一局域网内所有设备探测到，仅在你信任的 Wi-Fi 下开启。

主窗口与设置窗口共用 **Vue 3** 入口（`src/vue-src/`，Vite 构建为 IIFE 单文件 `src/webui/dist/ohmymeme.js`），通过 `pywebview.api.*` 桥接后端。`src/webui/settings.html` 是设置页挂载壳，模板、样式与原有表单逻辑位于 `src/vue-src/settings/`；自定义设置和 NapCat 监听状态轮询随入口一并保留。

## 实现要点

### 启动时序
启动分两阶段：首先 `get_init_data()` 秒开渲染数据库数据，随后执行 `rescan_cache()` → `run_auto_sync()` → `check_update()`。**动画开启时动画播放期间即并行加载**（动画天然覆盖桥接稳定时间，无 300ms 延时）；**动画关闭时降级 300ms 延时**（桥接稳定需要）。**先 rescan 再 sync**（文件与 DB 一致后再对比远端）。

### 缓存去重
开启设置 `bulk_read_protection` 后，首次建立日常副本、启动扫描、manifest 重建、备份、迁移和同步等批量读取会共用保护闸门：一次只读取一个原件，并按 `bulk_read_batch_size`（1–1000，默认 8）与 `bulk_read_pause_seconds`（0–60 秒，默认 1）分批暂停，以降低虚拟盘短时间内的请求密度。闸门分为关键交互、当前页和后台三级优先级；保存换类/改名、单图拖入可越过批次冷却并在当前单文件读取结束后优先执行，当前页读取又优先于后续页预热。启动缓存扫描是单例后台任务，前端调用会立即返回；扫描结束后再通知界面局部刷新，避免长期占用 pywebview 回调。单图导入提交后使用数据库数据增量追加 `meme-index.json`，不再为了完成上传而遍历原件；若完整重建已经占用清单锁，增量更新会立即放弃并合并一个后台重建请求。列表查询判断 WebP 动画只读取本地日常副本，不逐张探测网盘原件。额外开启 `bulk_read_prefetch_pages` 时，每次分页查询会取消旧预热任务，并从当前页之后按相同查询条件逐项补建日常副本和缩略图。

扫描缓存目录时**双重去重**：按文件名查 DB 防止每次启动重复注册，按 SHA-256 哈希查 DB 防止同图不同名重复。导入（拖入/对话框）同样有哈希去重。

### 原件与日常副本
通常 `cache_dir` 中的 `filename`/`file_hash` 代表原件，`data_dir/derivatives` 保存可再生的日常副本。若对超过 20 MiB 的普通媒体选择“仅保存压缩版”，压缩结果会直接成为 `cache_dir` 中的正式归档文件，数据库以 `compressed_only` 标记并以 `source_file_hash` 保留原始输入哈希用于去重，不会再留下原件或重复的 derivative；详情和右键菜单会明确提示无原件。静态图片转为质量 84 起步的 WebP 并把最长边限制到 1600px，GIF 保持 GIF，动画 WebP 保持动画 WebP，透明通道、帧时长和循环信息会保留。超大 JPEG 会先有界读取文件头：不超过 3 亿像素时在完整解码前使用 JPEG 原生降采样，超过则继续拒绝，不会全局关闭 Pillow 的安全保护。仅当原件本来就在 1600px、8 MiB 范围内且重新编码反而更大时，副本目录才保存原格式字节副本。网格动图、详情预览、普通复制和原生拖拽使用日常副本；仅压缩归档时使用正式归档文件。日常副本不进入备份或远程同步，丢失、版本过期、旧库升级、备份恢复或同步拉取后均会在首次使用时从原件自动重建。

缩略图位于 `data_dir/thumbnails`，日常副本与缩略图都会跨重启保留；删除表情时删除该表情对应的两类文件，清空本地数据时整体清理。目前没有按文件数量、访问时间或总容量自动淘汰的逻辑，历史配置项 `cache_max_size_mb` 也尚未用于清理。WebView 还会自行缓存当前页面已请求的图片，但其内存/HTTP 缓存由浏览器内核管理。开启“后台逐渐缓存后续页面”后，后台只持久化日常副本与缩略图，不会把全部后续页图片长期保留在网页 DOM 或应用图片对象中。

### GIF 剪贴板
Windows 上 GIF 复制同时写入三个剪贴板格式：`CF_DIB`（首帧 BMP）、`CF_HDROP`（文件路径，QQ/微信粘贴动图必需）、自定义 `"GIF"` 格式。**移除 CF_HDROP 会导致 QQ/微信粘贴 GIF 变静态图。**

### 复制处理模式
设置页「复制处理」下拉（配置 `copy_resize_mode`：0不处理；1webp缩放，默认；2转gif；3转gif隐写原图）：普通复制先取得日常副本，再对超过 `copy_resize_max`（默认 200px）的静态图按模式处理，动图（GIF/动画 WebP）不受影响。模式 1 继续转 WebP 缩放到限制内；模式 2/3 按日常副本分辨率转 GIF（模式 3 额外隐写日常副本，失败时复制日常副本）。右键「复制原件」完全绕过此流程。处理结果写入系统临时目录并按编码参数和版本复用缓存。

### 复制时避免 WebP
设置页「复制处理」区块内开关（配置 `copy_avoid_webp`，默认关闭）：微信等应用把复制的 WebP 当成文件而非图片，开启后复制路径上的产物一律不含 WebP —— 动图 WebP 转动画 GIF（保真帧延时、`disposal=2` 逐帧清空画布避免残影）、静态 WebP 转 JPG（带透明时合成白底）、非 WebP 的缩放产物输出 JPG（不透明）或 PNG（带透明），其中模式 1 开启时直接按目标格式编码，避免「先转 WebP 再转 JPG」的二次有损。库内文件、数据库、缩略图与同步均不受影响，仅在系统临时目录生成转换副本（`ohmm_webp_gif_<md5>_<上限>_v<版本>.gif` / `ohmm_webp_jpg_<md5>_q<质量>_v<版本>.jpg` / `ohmm_resize_<md5>_<max>_q<质量>_v<版本>.jpg` / `ohmm_resize_<md5>_<max>_v<版本>.png`）；转换失败回退复制原图并记录日志。**仅作用于复制到剪贴板，拖拽出库仍是原文件。**

### 加密降级
加密优先使用 `cryptography.fernet.Fernet`，不可用时降级为 `hashlib.pbkdf2_hmac` + XOR + base64。**不能移除 XOR 降级**，否则无 `cryptography` 时系统崩溃。

### Sync 集合合并
`pull` 时远端分组以**并集**方式递归合并到本地已有分组（不清除本地成员），包括没有成员的空层级。远端 manifest 中的 `collections` 用文件名关联（非 ID），跨设备稳定。远端标签与收藏同样以**并集**合并到本地（标签为条目内 `tags` 数组，兼容读取旧版顶层 `tag_map`；收藏为顶层 `favorite` 文件名数组；均只增不清，某端删除标签/收藏不会同步到其他端）。

### 标签写入同步清单
设置页「云端同步」区块开关（配置 `manifest_include_tags`，默认开）：开启时 `meme-index.json` 每个表情条目写入 `tags` 数组（无标签为 `[]`），随 push/局域网同步到其他设备；关闭时条目不含 `tags` 键（仅影响清单，本地标签不受影响）。标签编辑（单个/批量）后本地清单即时重建。

### 收藏夹写入同步清单
设置页「云端同步」区块开关（配置 `manifest_include_favorites`，默认开）：开启时 `meme-index.json` 顶层写入 `favorite` 文件名数组（无收藏为 `[]`），随 push/局域网同步到其他设备；关闭时整个 `favorite` 键不写入（仅影响清单，本地收藏不受影响）。接收侧合并不受该开关限制。

### Manifest 结构持久化
构建 `meme-index.json` 时会保留显式创建的空分组及其层级，使刚建立但尚未加入内容的路径也能跨设备同步。只修改表情标题时会在进程内加锁并原子更新清单中的对应 `name`，不会重新检查整库原件的 `exists/stat`；清单缺失、损坏或找不到对应文件时才回退到完整重建。

### 拖拽排序反馈
`canReorderMemes()` 仅在未搜索、未按标签筛选、当前为 ID 大于 0 的普通分组（含子分组）、且已开启拖拽排序时允许排序。此时普通表情卡最终为 `scale(0.95)`，带 3px `var(--border-light)` 描边和 3px 偏移，并以独立 `rotate` 属性作轻微快速晃动；正在拖拽、FLIP 让位、分页入场和文件夹卡均不晃动，系统减少动态效果偏好会禁用该动画。正在拖拽的卡独立使用最终 `translate(...) scale(0.90)`，保留现有透明度、阴影和 FLIP 效果，变换不得叠加。开启工具栏排序开关时沿用现有入场反馈；仅明确关闭该开关时保留当前卡片，以动画退场。搜索、标签筛选、切换分组或进入虚拟分组导致的资格变化均按普通刷新处理，不播放退场动画。

## 技术栈

| 模块 | 技术 | 理由 |
|------|------|------|
| UI | PyWebView (v6) + Bottle + Vue 3 | 原生 WebView 渲染，Vue 3 组件化前端（Vite 构建） |
| 托盘 | pystray | 最轻跨平台托盘库 |
| 热键 | keyboard → pynput → 轮询回退 | 三级降级保障 |
| 图片 | Pillow | 业界标准 |
| 剪贴板 | ctypes (Win32 API) | 零外部依赖，GIF 动画原始字节 |
| 数据库 | SQLite3 (WAL) | 内置，线程安全 |
| 加密 | cryptography (Fernet) | 轻量对称加密 |
| 窗口 | frameless + JS 拖拽 | 自定义无边框体验 |
